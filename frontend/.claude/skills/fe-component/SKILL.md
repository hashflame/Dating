# Компоненты

## Где живёт компонент

| Компонент                                       | Место                           |
| ----------------------------------------------- | ------------------------------- |
| Примитив без домена (кнопка, инпут, скелетон)   | `shared/ui/kit/`                |
| Свой переиспользуемый компонент                 | `shared/ui/<Имя>.tsx`           |
| Знает про предметную область                    | `domains/<домен>/ui/<Имя>.tsx`  |
| Собирает несколько доменов, нужен на 2+ экранах | `widgets/<виджет>/ui/<Имя>.tsx` |
| Часть одного экрана                             | `pages/<экран>/ui/<Имя>.tsx`    |

Уже готовые: `Button`, `Input`, `Checkbox`, `Skeleton`, `ProgressBar`, `Logo`,
`EmptyState`, `ErrorState` — из `@/shared/ui`. Сначала проверь, нет ли нужного там.

`shared/ui/kit/` — примитивы в стиле shadcn. Добавляются командой
`npx shadcn@latest add <имя> --yes` из папки `frontend`. Файлы кита исключены
из eslint и prettier: не правь в них стиль кода, правь только классы, если нужно.

## Один файл или папка

**Начинай одним файлом.** `MatchCard.tsx` рядом с остальными в `ui/`.

**Превращай в папку**, когда у компонента появляется второй собственный файл:

```
domains/matches/ui/MatchCard/
  MatchCard.tsx          разметка и логика компонента
  MatchCard.types.ts     типы ТОЛЬКО этого компонента
  MatchCard.helpers.ts   чистые функции ТОЛЬКО этого компонента
  MatchCard.module.css   CSS, если Tailwind не хватает (редко)
  index.ts               export { MatchCard } from './MatchCard'
```

Правила такой папки:

- Имя папки = имя компонента, `PascalCase`.
- `index.ts` содержит только реэкспорт, без логики.
- `.types.ts` — для типов, которые нужны и компоненту, и его хелперам.
  Тип пропсов из одной строки не выноси, оставь в `.tsx`.
- `.helpers.ts` — чистые функции. Как только хелпер понадобился второму компоненту,
  он переезжает: в `lib/` своего слайса или в `shared/lib`.
- Тип или хелпер, которые нужны за пределами компонента, в папке компонента не живут.
- Вложенные подкомпоненты, используемые только здесь, кладутся файлами в ту же папку
  (`MatchCardPhotos.tsx`) и не экспортируются из `index.ts`.

**Про стили.** По умолчанию — Tailwind-классы, отдельных файлов стилей не нужно.
Sass не подключён и не нужен: Tailwind v4 закрывает вложенность и переменные.
Если понадобился настоящий CSS (`@keyframes`, сложные селекторы, `content-visibility`) —
`<Имя>.module.css` рядом с компонентом. Глобальный CSS — только `app/styles/index.css`.

## Пропсы

```tsx
type MatchCardProps = {
  match: Match
  onOpen: (matchId: string) => void
  className?: string
}

export function MatchCard({ match, onOpen, className }: MatchCardProps) {}
```

- Тип пропсов объявляй отдельно, имя — `<Компонент>Props`.
- Деструктурируй в сигнатуре.
- `className?: string` — у любого компонента, который может встраиваться в чужую верстку.
- Передавай объект (`match`), а не набор полей (`matchId`, `matchName`, `matchPhoto`).
- Булевых флагов не больше двух. Три и больше взаимоисключающих — один проп-вариант:
  `variant: 'compact' | 'full'`.
- Пропсы-рендеры (`renderFooter`) — только когда `children` и композиция не подходят.

## Данные внутри компонента

Компонент домена может сам дёргать свой хук:

```tsx
export function ViewerBalance() {
  const { data, isPending } = useViewer()
}
```

Компонент, который нужен в разных контекстах, данные принимает пропсами.
Правило: **если компонент нельзя показать в другом месте без переписывания — данные внутрь.**

## Разбивай, когда

- JSX не влезает на экран (~60 строк) — вынеси логические куски в подкомпоненты.
- В компоненте больше трёх хуков состояния — вынеси логику в кастомный хук
  (в `model/` слайса или в `shared/hooks`, если он не про домен).
- Компонент не используется ни в одном экране — его не должно существовать.
- Один и тот же кусок верстки встречается третий раз — вынеси. Не раньше.
- Компонент рендерит и загрузку, и ошибку, и три ветки контента — раздели на
  контейнер (данные + состояния) и представление (чистый JSX).

## Три состояния — всегда

Любой компонент с запросом обрабатывает все три:

```tsx
const { data, isPending, isError, refetch } = useMatches()

if (isPending) return <Skeleton className="h-24 w-full" />
if (isError) return <ErrorState onRetry={() => void refetch()} />
if (data.length === 0) return <EmptyState description={t('matches.emptyHint')} />

return <MatchesList matches={data} />
```

Для строчных элементов вместо `EmptyState`/`ErrorState` допустим короткий текст —
но с комментарием, почему полноразмерное состояние не подходит.

## Мемоизация

React Compiler не подключён, но и преждевременная мемоизация не нужна.
Подробности и пороги — скилл `fe-performance`.

## Списки

- `key` — стабильный `id` из данных, никогда не индекс.
- Список длиннее ~50 элементов — см. `fe-performance`.

## Доступность и тач

- Кликабельно = `<button>`, а не `<div onClick>`.
- Минимальная зона нажатия — 44×44 px (`size-11` в токенах).
- Иконка без текста — `aria-label`. Декоративная иконка — `aria-hidden`.
