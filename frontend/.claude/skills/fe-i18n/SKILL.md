# Локализация

`i18next` + `react-i18next`. Языки: `ru` (по умолчанию), `be`, `en`.
Язык берётся из настроек Telegram-пользователя при старте.

## Главное правило

В JSX не бывает захардкоженного текста, который видит пользователь.

```tsx
const { t } = useTranslation()

<h1>{t('app.name')}</h1>          // ✅
<h1>Блізка</h1>                    // ❌
```

Исключение — имена собственные из данных (`{user.firstName}`) и цифры.

## Файлы

```
src/shared/i18n/locales/ru/common.json
src/shared/i18n/locales/be/common.json
src/shared/i18n/locales/en/common.json
```

Пока один namespace — `common`. Новый namespace вводим только если файл переваливает
за ~300 ключей; тогда его надо зарегистрировать в `shared/i18n/config.ts`.

## Ключи

Структура — по смыслу, не по экранам:

```json
{
  "action": { "continue": "Продолжить", "cancel": "Отмена" },
  "state": { "loading": "Загрузка…", "empty": "Пока ничего нет" },
  "onboarding": { "photos": { "title": "Добавь фото" } },
  "validation": { "nameTooShort": "Слишком короткое имя" }
}
```

Правила:

- Ключ описывает смысл (`action.continue`), а не текст (`action.prodolzhit`).
- Общие вещи — в `action`, `state`, `validation`. Специфичные — в раздел своей области.
- Глубина не больше трёх уровней.
- Ключ добавляется **сразу во все три файла**. Нет перевода — скопируй русский текст,
  чтобы приложение не показывало ключ пользователю.

## Плюрализация

```json
{
  "matches": {
    "count_one": "{{count}} мэтч",
    "count_few": "{{count}} мэтча",
    "count_many": "{{count}} мэтчей"
  }
}
```

```tsx
t('matches.count', { count: matches.length })
```

Русский и белорусский требуют формы `_one`, `_few`, `_many`. Не собирай формы
вручную через тернарники.

## Даты, числа, расстояния

Не переводи их ключами — форматируй через `useFormatters` из `@/shared/hooks`:
он берёт текущий язык и отдаёт `date`, `relativeTime`, `distanceKm`.

```tsx
const { relativeTime } = useFormatters()

<span>{relativeTime(like.createdAt)}</span>
```

Известное ограничение: в части движков у `Intl` нет данных для белорусского —
локаль `be` сводится к `ru`, и месяцы с относительным временем выводятся по-русски.
Формы числа (`Intl.PluralRules`) для `be` при этом работают правильно.
Если для конкретного места это критично — заведи ключи в локалях и не используй `Intl`.

## Интерполяция

```tsx
t('match.openedContact', { name: match.firstName })
```

```json
{ "match": { "openedContact": "Контакт {{name}} открыт" } }
```

Не склеивай строки из частей — в других языках порядок слов другой.

## Ошибки валидации

В zod-схемах в качестве сообщения храни ключ, а не текст (скилл `fe-forms`):

```ts
z.string().min(2, 'validation.nameTooShort')
```

## Типизация

Ключи типизированы по русскому файлу (`shared/i18n/i18next.d.ts`).
Опечатка в ключе не пройдёт `npm run typecheck`.

## Чего не делать

- Не вызывать `t()` вне компонента и хука — если нужен текст в чистой функции,
  верни ключ и переведи в UI.
- Не хранить готовые тексты в константах модуля.
- Не удалять ключ из одного языка, оставив в других.
