# Контракт API

Источник истины по API — папка `backend/` в этом же репозитории.
Генерации типов нет: типы на фронте пишутся руками и сверяются с бэкендом.

## Порядок действий

1. **Найди эндпоинт.** Ищи по имени сущности в `backend/`:

   ```bash
   grep -rn "matches" backend/src --include=*.cs -il | head -20
   ```

   Смотри на контроллеры (маршруты, методы, коды ответов) и на DTO/response-модели.

2. **Выпиши контракт** себе в задачу: метод, путь, query/body, форма ответа,
   что бывает при ошибке.

3. **Опиши тип на фронте** в `domains/<домен>/types/`:

   ```ts
   /** Мэтч. Сверено с backend: <файл, где лежит DTO>. */
   export type Match = {
     id: string
     userId: string
     createdAt: string // ISO-8601, парсить на месте использования
   }
   ```

   - Имена полей — как в JSON-ответе, не переименовывай.
   - Даты приходят строками. Держи их строками в типе, превращай в `Date` там, где нужно.
   - Не добавляй в тип поля, которых нет в ответе.
   - В комментарии укажи, откуда сверен контракт — это спасает при следующем изменении.

4. **Конверт уже развёрнут.** Бэкенд отвечает `{ data }` на успех и
   `{ error: { code, message, details, action } }` на ошибку; и то и другое
   разбирает `apiRequest`. В типе домена описывай только полезную нагрузку,
   без `data`.

5. **Проверь enum'ы.** Они сериализуются как camelCase-строки
   (`UserStatus.New` → `"new"`), поэтому на фронте это union строковых литералов,
   а не число.

## Эндпоинта ещё нет

Не блокируйся — ставь заглушку и фиксируй пробел.

```ts
import { stub } from '@/shared/api'

const FIXTURE: Match[] = [/* … */]

export function getMatches(): Promise<Match[]> {
  // @stub: эндпоинта нет в backend/ — см. docs/api-gaps.md
  return stub('GET /matches', FIXTURE)
}
```

Обязательные шаги:

1. Комментарий `// @stub: <причина>` над `return`.
2. Строка в `frontend/docs/api-gaps.md`: место в коде, что нужно от API, статус.
3. Фикстура — реалистичная: те же типы, похожие объёмы данных, крайние случаи
   (пустой список, длинное имя, отсутствующее фото).

`stub()` работает только в dev-сборке — в production бросает ошибку. Забытая заглушка
упадёт на сборке, а не тихо уедет в релиз.

## Эндпоинт появился

1. Замени `stub(...)` на `apiRequest(...)`.
2. Сверь тип с реальным DTO, поправь расхождения.
3. Удали строку из `docs/api-gaps.md`.
4. `npm run check`.

## Авторизация

Два шага, оба закрыты `apiRequest`:

1. `POST /api/auth/telegram` — сырой initData в заголовке `X-Telegram-InitData`,
   в ответ JWT. Это делает домен `session`, повторять не нужно.
2. Все остальные запросы — `Authorization: Bearer`, токен подставляется сам.

Руками заголовки не добавляй. Меняется формат — правится одно место:
`authHeaders()` в `src/shared/api/http.ts`.

## Чего не делать

- Не менять код в `backend/` — это другой пакет с собственными правилами.
- Не придумывать эндпоинты «как логично» без проверки по `backend/`.
- Не хранить фикстуры вне файла запроса — они должны исчезнуть вместе с заглушкой.
