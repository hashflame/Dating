# Стиль кода frontend

## Не дублируй: сначала посмотри, что уже есть

Перед тем как написать функцию, хук или тип, проверь существующее:

```bash
cd frontend
grep -rn "export function" src/shared/lib src/shared/telegram
ls src/shared/ui
```

Что уже готово и должно переиспользоваться:

| Нужно                                                      | Бери                                                             |
| ---------------------------------------------------------- | ---------------------------------------------------------------- |
| Склеить Tailwind-классы                                    | `cn` из `@/shared/lib`                                           |
| Даты, числа, расстояния                                    | `Intl`, локаль — из `i18n.language`; отдельных библиотек не надо |
| Кнопка, инпут, скелетон, спиннер, пустое состояние, ошибка | `@/shared/ui`                                                    |
| Запрос к API                                               | `apiRequest` из `@/shared/api`                                   |
| Формы слов по числу («2 зоркі»)                            | i18n с суффиксами `_one/_few/_many`, не своя функция             |
| Telegram: кнопка «Назад», хаптика                          | `@/shared/telegram`                                              |

Похожее почти подходит — расширь его (добавь параметр, вынеси общую часть).
Копия с другим именем — ошибка, которую вернёт ревью.

## Именование файлов

| Что            | Как              | Пример               |
| -------------- | ---------------- | -------------------- |
| Компонент      | `PascalCase.tsx` | `MatchCard.tsx`      |
| Хук            | `use-<имя>.ts`   | `use-matches.ts`     |
| Функция/модуль | `kebab-case.ts`  | `format-distance.ts` |
| Тип            | `kebab-case.ts`  | `match.ts`           |

## Именование сущностей

- Компоненты — `PascalCase`, существительное: `MatchCard`, `SwipeDeck`.
- Хуки — `useЧтоТо`: `useMatches`, `useSwipe`.
- Булевы — `is`/`has`/`can`: `isPending`, `hasPhotos`, `canSwipe`.
- Обработчики: проп `onSwipe`, реализация `handleSwipe`.
- Функции-действия — глагол: `sendLike`, `sendReport`.
- Константы-справочники — `SCREAMING_SNAKE_CASE`: `MAX_PHOTOS`.

Никаких сокращений, кроме общепринятых (`id`, `url`, `api`, `dto`).
`usr`, `btn`, `cnt` — нет.

## Типы

```ts
type Match = { id: string; userId: string } // ✅ type
interface Match {
  id: string
} // ❌ interface (кроме расширения типов библиотек)

const items: string[] = [] // ✅
const pairs: Array<[string, number]> = [] // ✅ для сложных типов

function send(id: string): Promise<void> {} // ✅ явный возврат у экспортируемых функций
```

- `any` запрещён. Не знаешь тип — `unknown` + сужение.
- `!` (non-null assertion) запрещён. Вместо него — проверка и ранний выход.
- `as` только при разборе внешних данных, с комментарием почему.
- Пропсы компонента — отдельный тип `<Имя>Props` рядом с компонентом.

## Экспорты

```ts
export function MatchCard() {} // ✅ именованный
export default MatchCard // ❌ запрещён линтом
```

Один файл — одна публичная сущность. Хелпер, нужный только этому файлу, живёт в нём же
и не экспортируется.

## Функции

- Ранний выход вместо вложенности:

```ts
if (!match) return null
if (match.isArchived) return <ArchivedNotice />
return <MatchCard match={match} />
```

- Вложенный тернарник запрещён. Три и более варианта — early return или объект-мапа.
- Больше трёх параметров — передавай объект.
- Функция длиннее ~40 строк или делает две вещи — разбей.

## Ошибки

```ts
import { isApiError } from '@/shared/api'

if (isApiError(error) && error.isNotFound) {
  return <EmptyState />
}
```

- В `catch` не глотай ошибку молча. Либо обработай, либо покажи пользователю, либо пробрось.
- `console.log` запрещён линтом. `console.warn` / `console.error` — только для реальных проблем.

## Комментарии

Пиши на русском. Комментируй **почему**, а не **что**:

```ts
// ✅ Telegram закрывает мини-апп на вертикальном свайпе — мешает свайпам ленты.
swipeBehavior.disableVertical()

// ❌ Отключаем вертикальный свайп.
swipeBehavior.disableVertical()
```

JSDoc — только там, где имя не объясняет всё. Комментарий, пересказывающий
подпись, вреден: он занимает место и устаревает первым.

```ts
// ❌ /** Возвращает возраст по дате рождения. */ function getAge(birthDate) {}
// ✅ /** Полных лет на текущую дату — не округляя вверх. */ function getAge(birthDate) {}
```

Держи комментарий в одну-две строки. Если объяснение не влезает — это либо решение
для `docs/architecture.md`, либо признак, что код надо упростить.
Комментарии-разделители внутри функции — признак, что функцию надо разбить.

## Порядок внутри файла

1. Импорты (порядок правит `npm run lint:fix`).
2. Типы и константы модуля.
3. Основная экспортируемая сущность.
4. Приватные хелперы ниже.

## Порядок внутри компонента

1. Хуки (в том же порядке: роутер → данные → стейт → эффекты).
2. Производные значения.
3. Обработчики.
4. Ранние выходы (загрузка, ошибка, пусто).
5. JSX.
