# Производительность

Приложение живёт в webview на телефоне: слабый CPU, мобильная сеть, палец вместо мыши.
Правила ниже — про этот контекст.

Часть правил взята из React-гайдлайнов Vercel Engineering (MIT) и адаптирована:
серверные и Next.js-специфичные рекомендации выброшены, у нас клиентский SPA.

## Сначала — не оптимизируй

Не добавляй `memo`, `useMemo`, `useCallback` «на всякий случай». Каждое из них
стоит памяти и усложняет чтение. Оптимизируй, когда:

- профайлер React DevTools показал проблему;
- список длиннее ~50 элементов;
- значение уходит в зависимости `useEffect` или в мемоизированный компонент;
- есть жалоба на подвисание.

## Ререндеры

**Считай производное во время рендера, а не храни в стейте.**

```tsx
const fullName = `${user.firstName} ${user.lastName}` // ✅
// ❌ useState + useEffect, который его пересчитывает
```

**Не объявляй компонент внутри компонента** — при каждом рендере это новый тип,
поддерево перемонтируется и теряет состояние.

**Не оборачивай простые выражения в useMemo.** `useMemo(() => a + b, [a, b])`
дороже самого сложения.

**Сужай зависимости эффектов до примитивов.** `[user.id]`, а не `[user]`.

**Побочный эффект от нажатия — в обработчике, а не в `useEffect` по изменению стейта.**

**Функциональная форма `setState`** там, где новое значение зависит от старого:
`setCount((prev) => prev + 1)`.

**Ленивая инициализация** для дорогого начального значения: `useState(() => compute())`.

**Часто меняющееся значение, которое не рисуется** — в `useRef`, а не в стейт
(позиция пальца при драге, счётчик кадров).

**Подписывайся на производный признак, а не на поток значений.**

```ts
const isEmpty = useFeedStore((s) => s.cards.length === 0) // ✅ меняется редко
const cards = useFeedStore((s) => s.cards) // ❌ если нужен только признак
```

**`useDeferredValue` и `useTransition`** для дорогого рендера от быстрого ввода:
фильтры ленты, поиск по интересам.

## Списки

- `key` — стабильный `id`, никогда не индекс.
- Длиннее ~50 элементов — `@tanstack/react-virtual` (пакет не установлен, обсуди перед добавлением).
- Дешёвая альтернатива для средних списков: `content-visibility: auto` на элементе списка.
- Вынеси статичный JSX за пределы компонента — он не должен пересоздаваться каждый рендер.
- Условный рендер тернарником, а не `&&`: `{count ? <Badge /> : null}` — `&&` с числом
  выводит `0` на экран.

## Бандл

Сейчас сборка одним чанком, ~500 kB / ~157 kB gzip. Держи это под контролем:

- Тяжёлый экран или редкая фича — `React.lazy` + `Suspense`.
- Большие данные (списки городов, справочники интересов) — загружай по требованию,
  а не импортом в бандл.
- Пути импортов должны быть статически видны сборщику: не собирай путь
  динамического `import()` из произвольной переменной.
- Новая библиотека — сначала проверь вес и есть ли уже похожее в зависимостях.
  Форматирование даты и чисел закрывается `Intl` (см. `shared/lib/date.ts`), не тащи `date-fns`.
- Предзагрузка по намерению: перед вероятным переходом дёрни `router.preloadRoute`.
- Dev-инструменты (моки, отладочные панели) закрывай проверкой `import.meta.env.DEV` —
  тогда сборщик их выбрасывает. Подробности и подводные камни — скилл `fe-telegram`.

Про барели: правило «не импортируй через barrel» из внешних гайдов относится к
огромным библиотечным `index`-файлам. Наши `index.ts` слайсов — короткие списки
именованных реэкспортов без `export *`, они хорошо тряхаются деревом.
Публичный API слайсов сохраняем (см. `fe-architecture`), а внутрь `shared`
импортируем точечно: `@/shared/lib/cn`.

## JavaScript

- Повторные поиски по массиву — `Map`/`Set` вместо `find` в цикле.
- Несколько проходов `filter().map()` по большому массиву — один проход или `flatMap`.
- `RegExp` — на уровне модуля, не внутри функции.
- Сортировка — `toSorted()`, чтобы не мутировать исходный массив.
- Минимум/максимум — один проход, а не сортировка.
- Чтение `localStorage` — один раз в память, а не на каждый рендер.

## Анимации и жесты

- Анимируй только `transform` и `opacity` — остальное вызывает пересчёт лэйаута.
- Свайп карточек — через `motion` (`drag`, `useMotionValue`), не через стейт на каждое движение.
- Слушатели `touchmove` и `wheel` — с `{ passive: true }`.
- Уважай `prefers-reduced-motion`.

## Изображения

Фото — основной вес в дейтинге:

- Всегда указывай `width`/`height` или `aspect-ratio`, чтобы не было сдвигов лэйаута.
- `loading="lazy"` и `decoding="async"` для всего, что ниже первого экрана.
- Первое фото карточки в ленте — `loading="eager"`, остальные ленивые.
- Размер запрашивай у API под экран, а не масштабируй огромный оригинал в CSS.

## Как измерять

```bash
npm run build          # смотри размеры чанков в выводе
```

- React DevTools Profiler — какие компоненты рендерятся и почему.
- Chrome DevTools → Performance с троттлингом CPU 4x — ближе к реальному телефону.
- Внутри Telegram: `VITE_DEBUG_CONSOLE=1` включает мобильную консоль.

Не оптимизируй по догадке: сначала измерь, потом правь, потом измерь снова.
