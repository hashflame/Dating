# Стили

Tailwind CSS v4, css-first. Файла `tailwind.config` нет — вся конфигурация
в `frontend/src/app/styles/index.css`.

## Цвета — только токены

Токены объявлены через переменные темы Telegram (`--tg-theme-*`), которые SDK
проставляет на `:root`. Цепочка такая:

```
тема телефона → тема Telegram-клиента → --tg-theme-* → токены приложения
```

Из этого следует главное правило: **светлую и тёмную тему не верстают отдельно.**
Пишешь один набор классов на токенах — обе темы получаются сами.
Класс `.dark` на `<html>` ставится автоматически, писать `dark:` не нужно.

| Токен                                        | Для чего                                |
| -------------------------------------------- | --------------------------------------- |
| `bg-background` / `text-foreground`          | фон и текст экрана                      |
| `bg-card` / `text-card-foreground`           | карточки, секции                        |
| `bg-primary` / `text-primary-foreground`     | основное действие (цвет кнопок клиента) |
| `bg-secondary` / `text-secondary-foreground` | второстепенный фон                      |
| `bg-muted` / `text-muted-foreground`         | подписи, подсказки, disabled            |
| `text-link`                                  | ссылки                                  |
| `bg-destructive`                             | удаление, блокировка, ошибки            |
| `border-border` / `border-input`             | разделители и рамки полей               |
| `ring-ring`                                  | фокус                                   |
| `bg-brand` / `text-brand-foreground`         | фирменный акцент «Блізкі»               |
| `text-faint`                                 | третий уровень текста: сноски           |
| `text-amber`                                 | зорки — внутренняя валюта               |
| `text-moss`                                  | «нравится», мэтч, успех                 |
| `text-cornflower`                            | информационные метки                    |
| `bg-tag`                                     | спокойная плашка под метки и кнопки     |
| `bg-track`                                   | утопленная дорожка: сегменты, слайдер   |

Запрещено:

```tsx
<div className="bg-white text-black" />        // ❌ сломается в тёмной теме
<div className="bg-[#f2607c]" />               // ❌ произвольный цвет
<div style={{ color: '#333' }} />              // ❌ инлайн-цвет
<div className="dark:bg-gray-900" />           // ❌ тема приходит из Telegram
```

Нужен цвет, которого нет в таблице — добавь токен в `index.css` (в `:root`,
`.dark` и `@theme inline`) и только потом используй.

Единственное исключение для `text-white` и `bg-white` — контент поверх фиксированной
тёмной подложки: фото, градиентные блоки (`bg-gradient-photo-*`), затемнение над
карточкой. Такая подложка от темы клиента не зависит, поэтому белый там корректен.
Оставь рядом комментарий, почему это не нарушение.

## Как проверить обе темы

В браузере в правом нижнем углу есть переключатель темы (только в dev-сборке
с `VITE_MOCK_TELEGRAM=1`): «как в системе» / светлая / тёмная. Выбор сохраняется
между перезагрузками.

Любую новую верстку прогоняй по всем трём положениям. Типичные находки:
текст, слившийся с фоном; рамка, невидимая в тёмной теме; тень вместо границы.

Если от темы зависит не цвет, а сам контент (другая картинка, другая иллюстрация) —
читай признак темы через `useSignal(miniApp.isDark)` обёрткой в `shared/telegram`.
Для цветов это не нужно: токены переключаются сами.

## Типографика

Шрифт один на всё приложение — Manrope (переменный, с кириллицей). Отдельного
шрифта под заголовки нет, второй шрифт не подключаем.

| Класс          | Что это           | Размер                     |
| -------------- | ----------------- | -------------------------- |
| `text-display` | заголовок экрана  | 28px, обычно с `font-bold` |
| `text-lg`      | заголовок блока   | 18px                       |
| `text-base`    | основной текст    | 16px                       |
| `text-tiny`    | сноска, пояснение | 13px                       |

Заголовки из двух и более слов — с `text-balance`, чтобы строки делились ровно
и верстка не ломалась на белорусском и английском, где текст длиннее.

## Размеры и отступы

Только шкала Tailwind: `p-4`, `gap-2`, `text-sm`, `rounded-lg`.

Макеты нарисованы в рамке 302px — это примерно 0.78 от реального экрана.
Размеры из макета переводи с коэффициентом ~1.3: 22px заголовок → `text-display`,
12.5px текст → `text-base`, 10.5px подпись → `text-tiny`. Копировать числа
из макета буквально нельзя — на телефоне это нечитаемо.
Произвольные значения `w-[137px]` — только для реально уникальных случаев, с комментарием.

Радиусы: `rounded-sm|md|lg|xl` — они привязаны к токену `--radius`.

## Safe area и высота

Мини-апп рисуется под шапкой Telegram и системными вырезами. Есть готовые утилиты:

```tsx
<div className="min-h-viewport pt-safe pb-safe" />
```

| Утилита                         | Что делает                                     |
| ------------------------------- | ---------------------------------------------- |
| `pt-safe` / `pb-safe`           | отступ под безопасную зону сверху/снизу        |
| `h-viewport` / `min-h-viewport` | высота окна мини-аппа без дёрганья при скролле |

Не используй `h-screen` и `100vh` — внутри Telegram они врут.

## Утилита cn

```tsx
import { cn } from '@/shared/lib'

;<div className={cn('flex items-center gap-2', isActive && 'bg-accent', className)} />
```

- Классы всегда через `cn`, если есть условия или внешний `className`.
- `className` от родителя ставится последним, чтобы его можно было переопределить.
- Не склеивай классы шаблонной строкой — `cn` разрешает конфликты Tailwind.

## Сначала посмотри, есть ли у примитива нужный проп

Прежде чем гасить поведение примитива своими классами — прочитай его файл
в `kit/`. Обычно нужное уже вынесено в проп, и правка сводится к одному слову.

Живой пример: `ToggleGroup` по умолчанию идёт со `spacing={0}` — это «сросшаяся»
полоса, где `rounded-none`, а крайние получают `first:rounded-l-md`
и `last:rounded-r-md`. В сетке карточек это выглядит как баг: первая и последняя
скруглены иначе, чем остальные. Лечится не переопределением радиусов
(они в вариантах `first:`/`last:`, и `cn` их не перебьёт), а `spacing={2}` —
группа перестаёт склеиваться. Тот же проп задаёт и `gap`, свой не нужен.

## Состояния — в вариантах примитивов, не в утилитах

Не заводи свои `@utility` под hover и active. Состояния описываются вариантом
в `shared/ui/kit/*`: там уже есть `hover`, `focus-visible`, `data-[state=on]`,
`disabled`. Нужна новая выбираемая поверхность — добавь вариант в `toggle.tsx`
(есть `surface`), а компонент задаёт только размер и типографику.

Поднятый элемент на дорожке (сегмент, полоса слайдера) — `bg-card` на `bg-track`,
а не на `bg-muted`. В тёмных темах Telegram `secondary_bg_color`
и `section_bg_color` часто совпадают, и тогда выбранный сегмент сливается
с дорожкой. `--track` считается от фона, поэтому контраст есть в обеих темах.

Три уровня поверхностей, одинаковые во всех компонентах:

| Уровень            | Токен          | Что на нём                                       |
| ------------------ | -------------- | ------------------------------------------------ |
| страница           | `--background` | фон экрана                                       |
| поднятый           | `--card`       | поля ввода, селекты, карточки, «пилюля» сегмента |
| утопленная дорожка | `--track`      | дорожка сегментов, полоса слайдера               |

В светлой теме `--card` совпадает с `--background` (оба белые) — поле читается
рамкой. В тёмной `--card` светлее фона, поэтому поле видно. Это даёт одинаковую
структуру в обеих темах без `dark:`-хаков.

Никаких `dark:` в разметке — и в `kit/` их тоже нет: пришедшие от shadcn
`dark:bg-input/30` убраны. Они красили поле только в тёмной теме и своим
оттенком, из-за чего поле не совпадало ни с фоном, ни с карточкой.
Фон поля задаёт `bg-card` — один токен на оба режима.

Акценты фирменные: `--primary` и `--ring` заведены на `--brand`, наведение —
нейтральный `--accent`, выбранное — `--brand-soft`. Синие акценты Telegram
в интерактивных состояниях не используем: они спорят с брендом.

## Тяжёлые примитивы импортируй прямым путём

`shared/ui/index.ts` попадает в главный чанк — его импортируют экраны запуска.
Всё, что он реэкспортирует, уезжает туда же, даже если нужно одному экрану.
Поэтому radix-примитивы (`toggle-group`, `select`, `slider`) и построенные на них
`SegmentedControl`, `OptionCard`, `RangeField` импортируются прямым путём:

```tsx
import { ToggleGroup } from '@/shared/ui/kit/toggle-group'
import { SegmentedControl } from '@/shared/ui/SegmentedControl'
import { Button, Field } from '@/shared/ui' // лёгкое — из бареля
```

## Варианты компонента

Три и более варианта оформления — `cva`, а не набор тернарников. См. `shared/ui/kit/button.tsx`.

## Порядок классов

Порядок правит `prettier-plugin-tailwindcss` — не сортируй руками, запусти `npm run format`.

## Мобильный контекст

- Приложение всегда узкое: базовые стили — мобильные, `sm:`/`md:` почти не нужны.
- Зона нажатия минимум `size-11` (44 px).
- Не полагайся на `hover:` — на тач-устройствах его нет. Обратная связь — `active:`.
- Длинные экраны скроллятся, липкие панели — `sticky bottom-0 pb-safe`.

## Когда трогать index.css

Только для: нового цветового токена, новой `@utility`, правки `@layer base`.
Компонентные классы в CSS не пишем — всё в Tailwind-классах рядом с разметкой.
