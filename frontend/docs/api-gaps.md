# Пробелы в API

Список мест, где фронт работает на заглушке или обходится неполным контрактом.

Правила:

- Заглушка ставится через `stub()` из `@/shared/api` и помечается комментарием `// @stub: …`.
- Каждая заглушка обязана быть в этой таблице.
- Когда эндпоинт появился — убираем заглушку и строку отсюда.
- В production-сборке `stub()` бросает ошибку, поэтому забытая заглушка не уедет в релиз.

## Заглушки

| Место в коде                           | Что нужно от API                                                                                                     | Статус                                                                         |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `src/domains/viewer/api/get-viewer.ts` | `GET /api/users/me`: профиль текущего пользователя — id, telegramId, имя, баланс зорок, флаг завершённого онбординга | эндпоинта нет: в `UsersController` только POST/PATCH/DELETE по фото и согласию |

## Неполный контракт

| Место в коде                                     | Чего не хватает                                                                                                                                                       | Как обходим                                                                                                                                                                                               |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/domains/session/lib/resolve-start-route.ts` | Нельзя узнать, дано ли уже согласие и на каком шаге онбординг: `POST /api/users/me/consent` есть, `GET` — нет; статус пользователя остаётся `new` до конца онбординга | Пользователь со статусом `new` каждый раз попадает на экран приветствия. Станет заметно, когда появятся экраны онбординга (T-2.1): нужен либо `GET /api/users/me/consent`, либо флаг в ответе авторизации |
| `src/shared/config/legal.ts`                     | Нет опубликованных Правил и Политики обработки персональных данных, версия документов не задана на бэкенде                                                            | Ссылки-заглушки на `blizka.app/terms` и `/privacy`, версия согласия зашита как `1.0`                                                                                                                      |
