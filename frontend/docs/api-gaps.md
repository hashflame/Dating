# Пробелы в API

Где фронт работает на заглушке или обходится неполным контрактом.

Правила:

- Заглушка — через `stub()` из `@/shared/api`, с комментарием `// @stub: …` и строкой в этом файле.
- Эндпоинт появился — убираем заглушку и строку отсюда.
- В production `stub()` бросает, поэтому забытая заглушка падает на сборке.

и `message-sent-check` (решение ниже).

## Заглушки

Одна фича целиком на заглушках — доска идей (T-19.1 помечена `POST-MVP`, на бэкенде
есть только сущности `Idea`/`IdeaVote`, ни контроллера, ни use-case'ов).

| Место в коде                               | Что нужно от API                          |
| ------------------------------------------ | ----------------------------------------- |
| `src/domains/ideas/api/use-ideas.ts`       | `GET /api/ideas` — список доски (S-60)    |
| `src/domains/ideas/api/use-create-idea.ts` | `POST /api/ideas` — `{ text, anonymous }` |
| `src/domains/ideas/api/use-vote-idea.ts`   | `POST`/`DELETE /api/ideas/{ideaId}/vote`  |

Чего не хватает в самом контракте T-19.1, помимо реализации:

- `?sort=hot|new` не покрывает вкладки макета «В работе» и «Мои» — нужен фильтр
  по статусу и по автору.
- В ответе нужен `hasVoted`: без него не показать, за что уже голосовал, и
  кнопка не может быть переключателем.
- `POST /api/ideas` должен сказать, начислена ли зорка за эту идею: бонус даётся
  раз в месяц, и человеку важно понимать, что идея принята, но зорки не пришли.

Остальные заглушки убраны: реферальные ссылки, блокировка и жалобы поехали на
реальные эндпоинты (T-20.1, T-16.2, T-17.1).

## Баги бэкенда

Отправлено бэкендеру 27.08.2026. Пока не починено — обходим или живём с этим.

| Что                                                     | Как проявляется                                                                                                                                                                                                                                          |
| ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Локаль ответа берётся из JWT, а не из `Accept-Language` | `RequestLocaleResolver` сначала читает claim `locale` (язык Telegram-профиля). Проверено живьём: интерфейс на русском, а вопрос дня приходит на английском, `earnOptions[].label` = «Registration bonus», `cityName` = «Minsk», интересы = «Video Games» |
| Баланс не сходится с журналом операций                  | `GET /api/sparks/wallet`: `balance: 38`, в `history` ровно одна запись `contactUnlock -1`, `totalCount: 1`. При этом `registrationBonus` помечен `completed: true` (+50). Начисления в леджер не попадают — история не объясняет баланс                  |
| `date-ideas`: город не подставляется                    | Хендлер берёт город только из query `?city=`, фолбэк — литерал «вашем городе», который не согласуется в шаблонах: «Прогулка по центру **вашем городе**»                                                                                                  |
| `unlock` списывает зорки, когда username нет            | `SpendAsync` идёт до проверки `other.TelegramUsername`; при `null` человек платит и получает `telegramUsername: null, deepLink: null`. Из кода; живьём не воспроизводили                                                                                 |
| Заблокированные остаются в симпатиях                    | После блокировки (в т.ч. через `report` с `blockUser: true`) человек по-прежнему приходит в `GET /api/likes/outgoing`. `LikesRepository` прячет `Status = Deleted`, но не смотрит в `UserBlocks`                                                         |
| `writesFirst` в списке мэтчей — заглушка                | В хабе `contactStatus` уже честный (`writes_first_only`), а `GET /api/matches` всегда отдаёт `writesFirst: false`                                                                                                                                        |

## Решено держать на фронте

Не пробелы, а решения — чтобы их не начали «исправлять» на бэкенде.

| Что                                         | Где живёт                                        | Почему так                                                                                                                                              |
| ------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Подписи в «Как заработать»                  | `profile.spark.*` в i18n                         | Сервер отдаёт `label` и `nextReward.hint` на локали из JWT (язык Telegram-профиля), а интерфейс может быть на другом. Прогресс и «получено» — серверные |
| `POST /api/matches/{id}/message-sent-check` | —                                                | «Получилось написать?» после перехода в Telegram не спрашиваем: это вопрос ради метрики в момент, когда человек занят разговором                        |
| Лимит «до двух целей знакомства»            | `MAX_GOALS` и zod-схема шага 2                   | Правило продуктовое, не про целостность данных: обойти можно только мимо интерфейса, вреда нет                                                          |
| Тексты Правил и Политики                    | `legal.*` в i18n                                 | Своего сайта у продукта нет, документы читают внутри мини-аппа. Перевод — часть интерфейса                                                              |
| Версия согласия                             | `CONSENT_VERSION` в `src/shared/config/legal.ts` | Уходит на сервер с меткой времени. Поднимать вручную при правке `legal.*` — иначе согласившиеся со старой редакцией не переспросятся                    |
