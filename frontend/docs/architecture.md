# Архитектура фронтенда

Живой документ. Обновляется, когда меняется структура — не задним числом.

## Слои

| Слой      | Что внутри                                                 | Может импортировать      |
| --------- | ---------------------------------------------------------- | ------------------------ |
| `app`     | точка входа, провайдеры, роутер, глобальные стили          | всё                      |
| `pages`   | экраны: композиция доменов и виджетов, без бизнес-логики   | widgets, domains, shared |
| `widgets` | составные блоки, переиспользуемые между экранами           | widgets, domains, shared |
| `domains` | предметные области: типы, запросы, стейт, UI домена        | domains, shared          |
| `shared`  | UI-кит, http-клиент, конфиг, i18n, Telegram, утилиты, хуки | shared                   |

Слайс = папка внутри слоя. Сегменты внутри слайса: `api/`, `model/`, `types/`, `ui/`, `lib/`.
Наружу слайс отдаёт только `index.ts`.

Направление импортов и публичные API проверяет `eslint-plugin-boundaries`
(конфиг — `eslint.config.js`, секция «Архитектура»). Нарушение = ошибка линта.

## Сегменты shared

| Сегмент    | Что внутри                                                                   |
| ---------- | ---------------------------------------------------------------------------- |
| `api`      | транспорт: `apiRequest`, `ApiError`, `stub`                                  |
| `config`   | `env`, константы путей роутов                                                |
| `hooks`    | переиспользуемые хуки: `useDebouncedValue`, `useDisclosure`, `useFormatters` |
| `i18n`     | инстанс i18next, локали ru/be/en                                             |
| `lib`      | чистые утилиты по темам: `cn`, `date`, `number`                              |
| `telegram` | обёртки над Telegram SDK                                                     |
| `types`    | типы-утилиты без предметного смысла                                          |
| `ui`       | переиспользуемые компоненты; `ui/kit` — примитивы shadcn                     |

## Ключевые решения

**Роутер на memory history.** Telegram передаёт launch params в `location.hash`
и управляет навигацией нативной кнопкой «Назад». Браузерная история конфликтует
с этим, поэтому URL не используется как источник состояния навигации.
Deep links приходят через `startParam`, а не через путь.

**Тема приходит от телефона, а не из приложения.** Цепочка: настройка системы →
тема Telegram-клиента → переменные `--tg-theme-*` на `:root` → токены приложения
(`--background`, `--primary`, …). Своей темы у приложения нет, светлая и тёмная
версии не верстаются отдельно. Класс `.dark` и `color-scheme` синхронизируются
по признаку `miniApp.isDark`. Фирменные цвета — отдельный токен `--brand`,
он от темы не зависит.

**Переключатель темы для разработки.** В браузере мок окружения отдаёт параметры
темы по `prefers-color-scheme`, а переключатель в `app/dev/DevThemeToggle.tsx`
позволяет форсировать светлую или тёмную. Он не подменяет тему в обход SDK, а
посылает то же событие `theme_changed`, что и настоящий клиент, — поэтому проверяет
рабочий путь, а не отдельную ветку кода.

**Dev-код отрезается на сборке.** Мок окружения, переключатель темы и мобильная
консоль закрыты проверкой `import.meta.env.DEV`, которую Vite сворачивает в
константу, так что модули выбрасываются из бандла целиком. Проверяется поиском
dev-строк в `dist/assets/*.js` после `npm run build`.

**Плоский слой domains вместо entities + features.** Один домен — одна папка,
без разделения «сущность/фича». Меньше решений о том, куда положить файл.

**Типы живут в двух местах, и это осознанно.** `domains/<домен>/types` — типы
предметной области (`Viewer`, `Match`): они принадлежат домену и меняются вместе
с его запросами. `shared/types` — типы-утилиты (`Nullable`, `RequireKeys`): они
про TypeScript, а не про дейтинг. Общая папка типов быстро превращается в свалку,
которую импортируют все и от которой нельзя отвязать ни один домен.

**Тот же принцип у api.** `shared/api` — транспорт, один на приложение: клиент,
класс ошибки, заглушки. `domains/<домен>/api` — конкретные запросы домена.
Транспорт общий, запросы принадлежат домену.

**Утилиты разбиты по темам, а не свалены в `utils`.** `shared/lib/cn.ts`,
`shared/lib/date.ts`, `shared/lib/number.ts`. Форматирование дат, чисел и расстояний
делает `Intl` — отдельные библиотеки для этого не нужны. Привязка к текущему языку
интерфейса — через хук `useFormatters`, чтобы локаль не передавали руками
в каждом вызове.

**Формы слов по числу — через i18n, а не через свою функцию.** Ключи с суффиксами
`_one/_few/_many` в локалях; `Intl.PluralRules` внутри i18next сам выбирает форму
для русского и белорусского.

**Известное ограничение белорусской локали.** В части движков (проверено в Chromium)
у `Intl` нет данных для `be`: локаль сводится к `ru`, поэтому названия месяцев и
относительное время для белорусского выводятся по-русски. Формы числа при этом
корректны. Если это станет заметно — переводим конкретные места ключами вместо `Intl`.

**Заглушки вместо ожидания бэкенда.** Нереализованные эндпоинты закрываются
`stub()` и фиксируются в `docs/api-gaps.md`. UI пилится независимо.

## Границы приложения

- Единственная точка обращения к API — `apiRequest` из `@/shared/api`.
- Единственная точка работы с Telegram — `@/shared/telegram`.
- Единственная точка чтения окружения — `@/shared/config/env.ts`.
- Переиспользуемые компоненты — `@/shared/ui`, хуки — `@/shared/hooks`,
  утилиты — `@/shared/lib`. Дубликаты вместо переиспользования не проходят ревью.
- Папка `backend/` — только для чтения контракта API.
