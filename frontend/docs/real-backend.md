# Как работать против реального бэкенда

Задеплоенный API: `https://api-production-3ead.up.railway.app`

## Что мешает открыть его прямо в браузере

Сам API из браузера доступен: `/api/health` отвечает, `/openapi/v1.json`
открывается. Упирается ровно одно место — вход.

`POST /api/auth/telegram` проверяет `initData` так
(`backend/src/Blizka.App/Telegram/TelegramInitDataValidator.cs`):

1. HMAC-SHA256-подпись строки по токену бота;
2. свежесть `auth_date` — не старше 5 минут.

Обхода для разработки в бэкенде нет — я искал. При `VITE_MOCK_TELEGRAM=1`
подпись подделана, поэтому сервер отвечает
`401 TELEGRAM_INIT_DATA_INVALID`, токена нет, и дальше экрана загрузки
приложение не идёт. Остальные эндпоинты требуют `Authorization: Bearer`,
поэтому без входа тоже отдают 401.

Второй момент — CORS. Бэкенд отдаёт заголовки только тем origin, что
перечислены в `Cors:AllowedOrigins`. Проверка: preflight с чужого origin
возвращает 204 **без** `Access-Control-Allow-Origin`. Поэтому не прописывай
адрес API в `VITE_API_BASE_URL` для работы в браузере — запросы заблокирует
браузер. Оставляй пустым и ходи через dev-прокси Vite: он серверный,
для браузера это тот же origin, и CORS не участвует.

## Запуск против реального API (внутри Telegram)

1. В `.env`:

   ```
   VITE_API_BASE_URL=
   VITE_API_PROXY_TARGET=https://api-production-3ead.up.railway.app
   VITE_MOCK_TELEGRAM=0
   ```

2. Поднять dev-сервер и выставить его в интернет по https — Telegram грузит
   Mini App только с публичного https-адреса:

   ```bash
   npm run dev:https
   ```

   и рядом туннель до порта 5173 (cloudflared, ngrok — любой).

3. В BotFather у своего бота указать полученный https-адрес как Mini App URL.

4. Открыть бота в Telegram. Клиент подставит настоящий подписанный `initData`,
   вход пройдёт, и приложение будет работать с реальными данными.

## Чего на деплое всё равно не хватает

Проверено 21.08.2026:

| Эндпоинт                 | Ответ |
| ------------------------ | ----- |
| `GET /api/cities/search` | 404   |
| `POST /api/geo/detect`   | 404   |

В исходниках `backend/` они есть, в задеплоенной сборке — нет. Пока её не
обновят, шаг «Где вы?» на реальном API не заработает: искать город нечем.
Подробности — в [api-gaps.md](api-gaps.md).

## Работа над экранами в браузере

Для этого и нужна локальная заглушка: она повторяет контракт, отвечает
теми же телами и кодами ошибок и не проверяет подпись.

```
VITE_API_PROXY_TARGET=http://localhost:5000
VITE_MOCK_TELEGRAM=1
```

Есть и третий путь — подписывать `initData` локально токеном бота и отдавать
его моку. Тогда реальный API заработает и в браузере, но токен бота нельзя
держать в репозитории, а подпись живёт 5 минут, так что её придётся
перегенерировать. Если нужно — скажи, добавлю dev-скрипт, который читает токен
из переменной окружения.
