# Тестовая Telegram-авторизация вне Telegram-клиента

Проблема: `POST /api/auth/telegram` проверяет HMAC-SHA256-подпись `initData` по токену бота
(`TelegramAuthMiddleware` → `TelegramInitDataValidator`, T-1.1) и свежесть `auth_date` (5 минут).
Вне настоящего Telegram-клиента подписать `initData` нечем — фронтенду не пройти дальше `401
TELEGRAM_INIT_DATA_INVALID`, и все остальные эндпоинты недоступны.

Обхода проверки в бэкенде нет и не планируется — это единственная точка входа в систему, ослаблять
её ради удобства разработки небезопасно. Вместо этого — [`scripts/generate-telegram-init-data.js`](../../scripts/generate-telegram-init-data.js):
локально считает **ту же самую подпись**, что и настоящий Telegram-клиент, так что бэкенд её
принимает как обычный боевой запрос. Код бэкенда не меняется и не ослабляется.

## Что нужно

- Node.js (только встроенный модуль `crypto`, зависимостей нет).
- Реальный токен Telegram-бота (`Telegram:BotToken`) того стенда, куда идёт запрос:
  - для локального `dotnet run` — значение из `appsettings.Development.yaml`/`BLIZKA_...`;
  - для задеплоенного стенда — значение переменной `Telegram__BotToken` в Railway.
  Токен вводится только в свой терминал и никуда, кроме локального вычисления подписи, не
  передаётся — не присылайте его в чат или тикеты.

## Как пользоваться

1. Сгенерировать `initData` (по умолчанию `userId=123456789`, `firstName=DevTester` — можно
   передать свои):

   ```bash
   BOT_TOKEN=<реальный_токен_бота> node scripts/generate-telegram-init-data.js 123456789 Тест
   ```

   Подпись валидна 5 минут (`auth_date`) — если не успели отправить запрос, сгенерируйте заново.

2. Обменять её на JWT:

   ```bash
   curl -X POST https://<хост-бэкенда>/api/auth/telegram \
     -H "X-Telegram-InitData: <вывод скрипта из шага 1>"
   ```

   Ответ содержит JWT. Дальше это уже обычный полноценный аккаунт — `user.id` в скрипте
   становится `TelegramId` пользователя в БД (при первом обращении заводится новая запись, как и
   для настоящего Telegram-пользователя).

3. Использовать JWT для всех остальных запросов: `Authorization: Bearer <токен>`. Живёт 24 часа
   (`Jwt:TtlHours`) — шаги 1-2 достаточно повторять раз в сутки, а не на каждый запрос. В браузере —
   вручную положить в тот же storage/заголовок, который использует фронтенд-клиент в проде для
   передачи JWT.

## Ограничения

- `initData`, подписанный токеном одного бота (например, локального дев-бота), **не примет**
  бэкенд, сконфигурированный на другой токен (например, прод-бот на Railway) — токены должны
  совпадать с тем стендом, к которому обращаетесь.
- Скрипт заполняет только `user.id`/`user.first_name` — этого достаточно для прохождения
  `TelegramInitDataValidator` (остальные поля `TelegramUserPayload` опциональны). Если нужно
  протестировать конкретные `username`/`photo_url`/`language_code`, добавьте их в объект `user`
  внутри скрипта под свою задачу.
